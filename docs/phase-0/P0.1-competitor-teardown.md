# P0.1 Competitor teardown

Research date: 2026-10-16. Sources are web search results. Direct page fetches failed in this environment, so App Store listings were not opened. Claims marked "(listing)" come from the developer's own App Store or website text.

No app is named exactly "Mac Remote". The closest are Remote Control for Mac (Evgeny Cherpak) and Control – Mac Remote Control (Ryan Whitney). Both are included.

| App | Does well | Gets wrong | What we take |
|---|---|---|---|
| **Remote Buddy** (IOSpirit) | Controls 100+ apps with per-app button mappings. Supports Apple Remote, Siri Remote, iPhone and Apple TV as inputs. Long track record. | Large paid Mac app with a deep settings tree. The iPhone remote historically was a web page served by the Mac, not a native app. Setup takes minutes before the first useful press. | Nothing from the feature set. Take the lesson: per-app integration is a rabbit hole. Media keys reach every app that supports them without per-app code. |
| **Rowmote Pro** | Long-lived, simple Wi-Fi remote. Trackpad and keyboard in the Pro version. | Dated UI that does not follow current iOS design. Two app tiers confuse buyers. | One app, one price. |
| **Remote Control for Mac** (Evgeny Cherpak) | Broadest feature set: media, volume, sleep, wake, app launching, AirPlay, trackpad, keyboard, live screen. Asks on the Mac to allow or deny each new device (listing). 2M+ downloads (listing). | Subscription or lifetime unlock for premium features (listing). The main screen has to serve many features, so the media controls are not the focus. | Per-device approval on the Mac. Our pairing code does the same job with less friction. |
| **Control – Mac Remote Control** (Ryan Whitney) | No Mac companion app. Uses AppleScript over Remote Apple Events (listing). Free. "Does not collect data" (listing). | Requires the user to turn on Remote Login / Remote Apple Events, which opens a system-wide remote-control surface on the network. Safari support is "experimental" (listing), which is our primary use case. Apple silicon only. Per-app AppleScript means apps not on its list do nothing. | Confirms the market wants zero-cost, privacy-first, minimal remotes. Confirms our choice of media keys over AppleScript for Safari/YouTube. |
| **Rimote** (rimote.app) | Same scope as Auvel v1: volume, media, sleep, lock. LAN only, PIN pairing, signed commands, fixed command set, no accounts or analytics. Free. Mac agent open source under MIT, notarised, 440 KB (site). | No confirmed weakness. Only the maker's site was reachable, so its design quality, multi-Mac support and App Store presence are unverified. v1.0.0, so no track record. | See finding F1 in the G0 summary. This is the direct competitor. Its fixed command set ("no shell, no scripts") is the right security posture and we match it. |
| **Apple: Control Center Apple TV Remote** | Native, instant, in Control Center. Hardware volume buttons control the target device. Large touch surface. | Apple TV only. Widely criticised for dropping dedicated previous/next buttons that the old Remote app had. | Large, single primary target. Keep explicit previous/next buttons. |
| **Apple: iTunes Remote** | Native, well-designed, free. | Controls only Music and TV apps via Home Sharing. Does not help with Safari or YouTube. | Clean device picker pattern at the top of the screen. |

## Gaps Auvel fills

1. G-a Safari/YouTube works as a first-class case, through media keys, without per-app scripting.
2. G-b Setup is short enough to measure: install to first pause in under 3 minutes.
3. G-c Current iOS design language. Most competitors look dated.
4. G-d Multiple paired Macs in one picker.
5. G-e Open source and local only, with a published threat model.

Rimote covers G-a, G-c (unverified), G-e and possibly G-d for free. Auvel's paid position rests on G-b, design quality and the wider Auvel ecosystem.
