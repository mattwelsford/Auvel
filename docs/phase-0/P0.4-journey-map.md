# P0.4 User journey map

From App Store discovery to daily use. Each step lists the target time, every point where a user can fail or quit (X codes), and the fix. The time column is the budget for the "install to first pause in under 3 minutes" done criterion, which starts at iPhone app install (J3).

| Step | What happens | Budget | Failure points and fixes |
|---|---|---|---|
| **J1 Discover** | User searches "mac remote" or "control mac from iphone" and finds Auvel. | — | **X1** User does not notice it needs a Mac app, buys, leaves a 1-star review. Fix: subtitle and first screenshot say "Needs free Auvel for Mac". First line of the description says the same. |
| **J2 Buy** | US$4.99 upfront. | — | **X2** Free alternatives exist (F1). Fix: screenshots sell design and setup speed. Listing states "Open source. Build it yourself free, or buy it here to support the project." Honest, and matches C3. |
| **J3 First launch (W1)** | One screen: three steps, "Send Mac Link…", "It's Installed". | 0:00–0:15 | **X3** User is on the phone and the download must reach the Mac. Fix: "Send Mac Link…" opens the share sheet, where AirDrop puts the page straight on the Mac. Short URL `getauvel.com/mac` shown as text. **X4** User has no Mac nearby now. Fix: link also goes to Notes/Mail. App remembers it is on step 1. |
| **J4 Install Mac app** | Download DMG from the site, drag to Applications, open. Homebrew is the secondary path. | 0:15–1:00 | **X5** Gatekeeper warning. Fix: Developer ID signed and notarised (C2), so only the standard "downloaded from the internet" prompt shows. **X6** Menu bar icon hidden behind the notch or a full menu bar. Fix: first launch opens the onboarding window (M3), which says "Auvel lives in the menu bar". **X7** User does not know Homebrew. Fix: DMG is the primary button, Homebrew is a text line. |
| **J5 Accessibility permission (M3)** | User opens System Settings, turns on Auvel under Accessibility, returns. | 1:00–1:40 | **X8** Highest drop-off point. The user leaves the app, navigates a settings pane, may enter a password. Fix: button deep-links to the Accessibility pane. Window polls `AXIsProcessTrusted()` and advances by itself. Short looping video shows the toggle. **X9** User refuses the permission. Fix: "Later" still pairs. Volume and mute work without it. iPhone shows play/pause disabled with "Allow on your Mac". **X10** Permission lost after an update. Fix: every release signed with the same Developer ID team so macOS keeps the grant. Build-from-source page warns that ad-hoc builds lose the grant on each rebuild. |
| **J6 Mac local network prompt** | macOS 15 and later may ask to allow Auvel to find devices on the local network when it starts advertising over Bonjour. | inside J5 | **X11** User clicks "Don't Allow". Fix: M3 says what the prompt will ask before it appears. Mac app detects the denial and shows a menu item linking to Privacy & Security › Local Network. Confirm exact trigger on hardware at P3. |
| **J7 iPhone local network prompt** | iOS asks to find devices on the local network when the Mac list opens. | 1:40–1:50 | **X12** User taps "Don't Allow". Every later step fails silently. Fix: one-line explanation shown before the system prompt. App detects `NWBrowser` policy denial and shows a Settings link instead of an empty list. |
| **J8 Pair (W2, M2)** | User taps the Mac in the list and types the 6-digit code from the Mac window. | 1:50–2:20 | **X13** Mac not found: different network, guest Wi-Fi with client isolation, VPN, mesh network blocking multicast. Fix: "Not listed?" checklist under the list. Manual address entry logged in backlog (B3). **X14** Wrong code. Fix: shake, haptic, clear, retry. Five failures expire the code and the Mac shows a new one. **X15** Code window closed. Fix: "Pair an iPhone…" in the menu reopens it with a new code. |
| **J9 First pause** | User taps play/pause. YouTube in Safari pauses. | 2:20–2:40 | **X16** Media key goes to a different app, for example Music starts playing (F6). Fix: pairing success screen says "Start a video in Safari, then tap Play/Pause". T6 matrix covers Safari, Chrome, Music, Spotify. **X17** Nothing happens because Accessibility was skipped (X9). Fix: disabled state with explanation, covered above. |
| **J10 First volume change** | User drags the volume bar. | 2:40–2:50 | **X18** Output device has no software volume, for example HDMI or DisplayPort displays and some USB DACs (F7). Fix: Mac reports that volume is not settable for the current output. iPhone shows "Volume for [device] is controlled on the device" and disables the bar. |
| **J11 Daily use** | User opens Auvel, it reconnects, user pauses or changes volume. | target under 1 s to usable | **X19** Slow reconnect after unlock because iOS closed the connection in the background. Fix: reconnect on foreground, resolve the Mac by Bonjour service name, not stored IP. **X20** Mac asleep or Auvel quit. Fix: W6 states the likely causes. Mac app defaults to Open at Login. **X21** Wrong Mac controlled when several are paired. Fix: Mac name is always shown at the top, and the last-used Mac is restored on launch. **X22** Phone locks while used as a remote. Fix: "Keep screen awake" setting. **X23** User sleeps the Mac and cannot wake it. Fix: sleep sits behind a confirmation that says Auvel cannot wake it. Wake-on-LAN logged in backlog (B2). |
| **J12 Updates** | Sparkle updates the Mac app. App Store updates the iPhone app. | — | **X24** Protocol mismatch between an old Mac app and a new iPhone app. Fix: versioned protocol (P2) with a "Update Auvel on your Mac" state. |

## Budget check

J3 to J10 totals 2:50 if each step meets its budget. J5 is the risk. The 3-minute target is achievable only if the Accessibility step stays under 40 seconds. This is measured with the 3 test users in the done criteria.
